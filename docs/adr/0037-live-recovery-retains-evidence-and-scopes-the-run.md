# Live recovery retains evidence and scopes the run

Status: accepted. Issue: #264; live rollout: #263.

A recovery rerun needs its earlier failure and rollback evidence. Ordinary morning maintenance
purges expired artifacts and replaces its same-day report; its prelude also updates the shared
textbook shelf and configured Research-project task mirrors. Those effects exceed a request
limited to active Modules.

The morning command accepts explicit retention and Module-only scope. Retained runs exclusively
claim a private directory, preserve reports and partial execution evidence, and skip ordinary
purge. Module-only runs select active Module task targets before constructing providers and
report the shared-shelf step as skipped. Existing scheduled behavior stays the default.
Scoped reports have distinct managed issue identities, so they cannot overwrite or resolve
failures from a broader pass whose excluded domains remain unobserved.

An invocation may request Sol and a supported reasoning effort together. Validate both before
loading configuration or starting work; record requested settings, scope and retention before
the prelude. Keep the existing workspace sandbox. Invocation metadata establishes the request,
not attestation of the serving model or maintenance correctness.

Live recovery remains an authorized, backed-up application followed by per-Module evidence:
completed sessions, complete write journals, domain outputs and independent postflight checks.
Retained artifacts, a corrected executable path and current imports answer narrower questions.
