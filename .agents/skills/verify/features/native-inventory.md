# Native inventory

The read-only migration boundary observes complete native representation on a physical, quiescent macOS root.
Its result supplies source evidence for later planning. It grants no migration or copy-admission authority.
The [native inventory contract](../../../../docs/native-inventory.md) defines encodings, limits and the non-atomic observation boundary.

## Drive

Use the parent skill's isolated fixture environment and a fresh doctor.
On macOS, `native-inventory-compiler` observes the Command Line Tools rebuild prerequisite.
The compiled inventory journey also proves that a bound adapter runs with an unavailable compiler toolchain.
The discovery workflow invokes the compiled `migration inventory` CLI against disposable sources.

```sh
node dist/src/cli.js capabilities verify --workflow discovery --json --log "$aos_proof/native-discovery.json"
```

Require `passed` and passed child checks. Inspect the retained fixture evidence under `$aos_proof/fixtures`.
The capability index maps the action to `test/migration/native-inventory-cli.test.ts` and its portable boundary assertions.

On macOS the native journey checks dot files, scratch directories, `Icon\r`, `.DS_Store`, file hashes, hardlink groups, internal, outward and dangling links.
It observes raw link targets, actual ACL payloads, flags, birthtime, xattrs and resource-fork bytes.
It refuses source changes and root or external hardlink aliases, leaves outward targets unchanged, and marks FIFO metadata incomplete without opening the FIFO.
It checks exclusive private logs outside source and repository.
Case and Unicode aliases of source and disposable repository roots must refuse before namespace or modification/change times advance.
Native `ln -P` fixtures retain internal symlink hardlink groups and refuse external symlink aliases.
Portable accounting also retains non-directory special-file hardlink relations without establishing native metadata coverage.

A non-UTF8 filename is attempted. A filesystem rejection with `EILSEQ` is reported as unreachable native filename coverage.
Portable schema and aggregation tests still exercise exact non-UTF8 path bytes. Raw non-UTF8 symlink targets are exercised natively.
Device entries and dataless placeholders require host privileges or provider fixtures unavailable to this journey.
Portable tests cover those result shapes and ensure unavailable representation prevents completeness. They do not establish native device or hydration behavior.

Linux returns `unsupported-platform` and runs portable boundary tests. It does not observe Darwin metadata.
The helper binding ties source and executable hashes to this build. It does not attest the compiler.
The v2 binding requires the ordered `scan.c`, `scan-core.c`, `scan-core.h` closure.
After changing this closure, run `node .agents/skills/control-publication/scanner-binding.mjs`
in the same private temporary-directory environment. Read its printed `result.json` and command records.
It physically copies the compiled CLI and dependencies, refuses reordered, omitted, duplicate and extra
members, unknown encoding and current sources mislabeled as legacy. Each refusal must return
`invalid-adapter-binding`; exact restoration must recover the original source fingerprint.
Its copied-adapter guard mutant admits the reordered binding. Restoring the actual order check must
recover refusal, then restoring the binding must recover complete observation.
The v1 route remains supported for the pinned single-file formatter hash. Removing it requires an
explicit installed-helper compatibility change. A v2 build without its encoding is not a v1 helper.

The discovery journey compiles the actual core with a C++ consumer. It checks two passes, a 65,537-byte
resource fork delivered in at most 65,536-byte fragments, sixteen `value_bytes` callback stops,
unchanged descriptor count and a successful subsequent pass. Other callback stop paths and borrowed
view lifetimes remain source-inspected premises, not exhaustive native memory-safety proof.
Public fixtures also check files above 64 MiB, signed dates, changing directory membership and
depth 256 versus 257. Native entry/allocation ceilings remain finite runtime bounds.
The two walks detect observed changes. They do not prove an atomic snapshot or safety against arbitrary hostile syscall races.
A source fingerprint includes inode, device and change time and therefore cannot serve as copy-preservation equality.
