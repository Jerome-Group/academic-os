# Capability evidence

Start with the compiled CLI's `capabilities index --json`. Its action metadata is the
feature-to-verification map. Inspect the selected action's prerequisites, effects and risk flags
before invoking it; ordinary diagnostics can still write private observations or mirrors.

`capabilities health` observes local tool readiness. A configured executable's existence establishes
readiness, while successful maintenance requires a completed pass, schema-valid domain evidence
and independent postflight checks. Fresh importer receipts establish a separate observation.

Use `capabilities verify` for disposable fixture journeys and `capabilities check` for quality
profiles. They return structured status, exit codes, durations and evidence digests. Preserve a
failed run's private evidence and retry the same bounded workflow after fixing its cause. CI calls
these entrypoints too. Optional logs belong outside the repository and every academic mount.
Configured health rejects aliases into its declared mount. Other actions cannot discover private
mount configuration: select a private local-state or disposable temporary destination explicitly.

Completion requires accounting for every requested feature and unresolved result. Structural,
portable, mathematical and visual evidence answer different questions. Review every rendered
page and source qualification before recording mathematical or visual review against its exact
PDF hash. Missing tools or unread sources remain explicit limits.

Synthetic scenarios use temporary roots and injected providers. Live writes and maintenance reruns
require separately scoped target authority and the applicable recovery/containment procedure in
[`safe-drive-testing.md`](safe-drive-testing.md). Keep coursework, credentials, private paths and
free-form operational evidence in private state; public findings carry only safe summaries.

For authorized Module recovery, select the morning action's explicit retention, Module-only scope
and paired model/effort options from the index. Retention preserves existing artifacts; scoped
settings belong to that invocation. Verify every Module's session and journal before resolving a
maintenance failure. A refusal or parked decision remains visible even after successful execution.
