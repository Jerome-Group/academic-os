# Weekly maintenance review

Daily execution, weekly attention. The existing morning launcher maintains the configured
Modules, runs bounded repository repair, records private daily evidence and updates one public
review for the Monday-start week in `Asia/Singapore`. Its first successful publication creates
the issue even on a quiet week. A missed Monday creates it on the next run.

The CLI capability index owns executable prerequisites, effects, options and verification.
Discover `routine morning`, `routine repository-repair` and `routine repository-status` there.
Module-only recovery excludes repository repair and shared-shelf writes. It updates its exact
coverage scope within the same weekly issue; it cannot resolve a broader observation.

## Fixed public format

`Weekly maintenance review <Monday date>` has these managed sections:

| Section | Evidence it carries |
| --- | --- |
| Overview/Coverage | Observed exact scopes, pending scopes and stale observations |
| Merged repository fixes | PR number, merge commit, combined-main verification and rollout verification |
| Verified maintenance | Evidenced maintenance, checks and control writes; details remain private |
| Unresolved work | Pending work and transferred incident references; transfer is not resolution |
| Awaiting verification | Missing or incomplete observations and unverified repair/rollout work |
| Verification limits | What the available evidence cannot establish |
| Owner notes | Owner-maintained text outside the generated block |

Keep merge facts throughout the week, including fixes discovered after interrupted publication.
Read-only GitHub discovery supplies PR/commit facts; absent verification receipts remain awaiting.
Unfixed work covers observed Module maintenance, the repository repair checkpoint and transferred
incidents. An unrelated open GitHub issue is not inferred fixed or automatically adopted by this
controller. Week-wide maintenance totals conservatively deduplicate same-day reruns; they count
evidenced entries and writes, not distinct defects.
Rollover retains completed fixes in their original week, carries unresolved verification forward
and bounds maintenance receipts to the current week.
Preserve Owner text and other scopes. Before retiring a predecessor, privately snapshot its original
body, publish the successor, verify readback, close with a fixed safe transfer comment and verify
the closed state with the original body unchanged. Historical
unknowns stay unknown until evidence resolves them. Legacy bodies are never copied into new public
prose. Malformed ownership, changed bodies or interrupted mutations require reconciliation.

## Daily repository repair

Green repository checks dispatch zero model workers. A new evidenced check failure permits one
bounded Sol/medium implementer and two independent Sol/medium reviewers in isolated checkouts.
Repeated unchanged failures reuse checkpoints rather than consuming another set of workers.
Pending required checks are re-observed without repeating implementation or review.
Check-only runs retain separate observations and leave repair checkpoints and attempted-failure
fingerprints intact. The status operation reads the latest normal repair checkpoint; a diagnostic
check does not replace a pending PR or claim that a repair was attempted.
Healthy diagnostics may retire an owned unchanged checkout containing only dependency/build output.
Rendered synthetic artifacts stay in a separate private fixture area. Unexpected checkout files,
failed checks and model-used checkouts preserve the checkout and its evidence. Cleanup refusal is
separate from check success; storage improvements require an actual measurement.

Eligible repairs stay within the controller's public code/test allowlist and add a synthetic
regression. Dependency, workflow, security, credential, normative contract, skill and controller
changes require ordinary reviewed repository work. Model output supplies a candidate; the controller
owns issues, commits, publication, exact-head checks and protected squash merge. Branch protection,
fresh base, resolved review findings and threads, and every required check remain merge gates.

Changed code and checks execute under the installed Codex sandbox with network disabled and temp
variables rooted in an exclusive private fixture area alongside the checkout. Exact grants cover
the checkout and fixture area; controller receipts and other siblings stay outside. Independent
synthetic probes cover external writes,
symlink escapes and network binds. This boundary permits external reads: it does not establish
confidentiality isolation. Apps, plugins, browser/computer tools, hooks and inherited MCP servers
have separate per-invocation disabling/preflight gates: connector traffic is outside the shell
network boundary. Metadata verification does not attest future serving-tool exposure. Workers use
public repository material and synthetic fixtures; private
diagnostics remain in retained local state. Backend identity and hard token limits are unverified.
Timeouts and attempt counts bound execution; they do not claim token consumption measurements.

A merged PR, successful combined-main checks and successful rollout are separate facts. Rollout
requires a clean primary checkout still at the observed baseline; unrelated changes remain intact.
Unknown mutation outcomes retain their lock and evidence for reconciliation. Read status before
retrying; a new healthy process does not reconcile an interrupted mutation.

For an interrupted mutation, run `routine repository-status --config <private-config> --json`.
Read the reported private evidence and its intent/result receipts; inspect the owned issue marker,
candidate branch/head, PR state and merge commit through read-only `gh`/`git` queries. Compare them
with the last persisted stage before proposing recovery. A pending-checks checkpoint resumes through
the ordinary repair entrypoint without new workers. Unknown publication, merge or conclusion
outcomes retain their lock: preserve the receipts and a concrete reconciliation handoff for an
authorized agent. This interface does not provide an automatic lock override.

This repair authority covers repository code. Existing Module Maintenance still owns precedented
source-backed upkeep. Live course recovery, structural cleanup, pinned refresh, actual academic
authoring and external Task/Calendar writes retain their separate target-specific authority.

## Completion evidence

Use the mapped synthetic lifecycle, controller and CLI tests, full repository checks and independent
review against the exact head. `rule-coverage:check` runs every compiled test, including privacy,
before checking normative rule evidence; `capabilities check --profile full` includes it.
Inspect the rendered weekly issue and retain migration snapshots outside ordinary report/session
purge. Post-merge check-only repository execution verifies the deployed entrypoint without a model
worker or a live Module maintenance replay. Future scheduled execution remains unobserved until it
actually fires.
