# Capability evidence belongs to the repository

academic-os owns a machine-readable capability index and bounded verification entrypoints beside
its CLI. The index maps supported actions to prerequisites, effects, risks and tests. Existing
commands retain their domain authority; discovery and fixture verification grant no live-write
authority.

Waiting for an organisation framework would leave a fresh agent relying on prose caches and
inconsistent command behavior. A local interface is useful now and needs no pstack dependency.
CI uses the same quality and synthetic workflow entrypoints agents can discover.

## Consequences

The catalog must evolve with dispatch and test coverage; structural checks detect missing actions
and broken test pointers. Fixture results establish only their tested behavior. Local readiness,
live recovery and mathematical/visual correctness retain separate evidence. Private logs remain
outside publication and carry bounded, reproducible diagnostics.

## Revisit when

An organisation interface can consume this catalog without weakening its effects, evidence or
authority boundaries. Adoption should replace an adapter rather than create a second policy.
