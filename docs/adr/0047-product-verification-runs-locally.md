# Product verification runs locally

Academic OS serves one person. The Owner directs it to use local agent verification and hosted
Organisation conformance only, following the Organisation-only CI precedent in Media Server.
The repository retires its product CI workflow rather than keeping a reduced hosted copy of
local checks. This is an explicit repository exception to `CODING_STANDARDS.md` §5.

Local agents retain the existing capability profiles, package commands and assertions. The
project verify skill owns fixture journeys and evidence retention. The separate seed-ownership
skill owns bounded formal models, source bindings, compiled schedules and mutation controls.
Relevant local checks and independent review precede pull-request delivery. `full` remains the
complete local check. Workflow retirement alone does not require repeating heavy checks when
their covered source bytes and assertions are unchanged and retained proof remains applicable.

Organisation conformance, label stamping and conformance-pin automation keep their existing
owners and workflows. The Organisation's policy and required contexts must agree with the
retired workflow while retaining unrelated protections. No replacement product check reports
synthetic success or skipped work.
Organisation policy reconciliation is tracked separately in
[org#289](https://github.com/Jerome-Group/org/issues/289).

Hosted conformance establishes policy compliance. It supplies no product build, behavior,
rendered-template or formal evidence. A local pass establishes its actual platform and tested
assertions only. Linux-specific behavior requires a local Linux run before a Linux claim.
Credentials, live providers, mathematical correctness and visual review retain separate evidence.

Revisit hosted product checks when another contributor or deployment needs continuous remote
product evidence that local verification cannot provide.
