# Generated Module activity evidence

The three actions in `src/module-activity/actions.ts` own CLI and MCP names, input and output
schemas, prerequisites, effects and handler bindings. CLI actions take `--input <packet.json>`
or `--input -`. Discover their current mappings through `capabilities index --json`.

This protocol records attributed evidence in host-owned generated candidates. It does not invoke
`/learn`, admit a live Module, create native artifacts, submit work, award official marks or write
providers. A published closeout completes a control operation. Its session status remains separate.

## Recognition

`src/controls/activity-registry.ts` binds 22 exact retained full Teaching Procedures to their
literal Module codes and exact shared preference bytes. Twenty-one permit single-topic revision.
MH3220 permits an exact contiguous topic block within one unit, with a retained grouping judgment.
There is no normalization or prose interpreter.

The retained shared Markdown has no native ID or version. `retained-teaching-preferences` and
`registry-1` are newly assigned canonical binding identities for its exact bytes. They do not
claim to be original document metadata. Local refinements and session instructions other than
the supported grouping judgment require further reviewed meaning.

All 22 real profiles require a revision note or source-bound verified reuse. Native admission is
unavailable, so these closeouts retain supported coverage and always park that output prerequisite.
The explicitly synthetic retained-only bindings can complete a synthetic control operation with
an evidenced no-output disposition. Their completion establishes no real lesson or artifact result.
Lecture, tutorial and past-paper targets remain readable and return unsupported native prerequisites.

## Protocol adoption and history

Generation 2 keeps its 18 roles. The undeployed Module-data draft adds only optional
`LearningWorkspaceControl.activityProtocol` and `LearningRecordsControl.activityCloseouts`.
Absent protocol means readable controls with unavailable activity workflows.

A directly enabled first generation requires empty records, assessments and closeouts. Historical
records first enter a protocol-free baseline. Adoption preserves that baseline and its evidence,
then adds a recognized protocol and an empty closeout list through ordinary raw publication.
Enabling the protocol does not establish Owner consent or accept a standing decision.

Once enabled, every appended current record has one rederived closeout. Raw publication uses the
same temporal validator inside the existing publication owner. It compares the actual predecessor,
retained preparation and submission descriptors, exact record and evidence regions, dependencies
and unchanged role bytes. Protocol rebinding and historical rewrites require a separate migration.

## Portable evidence and retry

Preparation binds the exact selected head, manifest, controls, retained dependencies, procedure,
preferences, target, requested scope and source order. Submission freezes the exact successor bytes
and logical result. Close rederives the original plan before passing those bytes to the publisher.
No activity session store, account namespace, lock or request lookup service exists.

Same-request replay returns its original logical result and receipt with the separately observed
current head. A changed binding refuses. A stale first request refuses after the publisher settles
earlier pending work. No academic merge occurs.

Complete input, preparation, plan, output and MCP envelopes have an 8,388,608-byte ceiling.
Encoded byte lengths, exact decoded lengths and digests are checked before byte allocation.
Activity MCP IDs have a 258-byte encoded JSON limit, checked before invoking a handler. Existing
Task and publication tools retain their JSON-RPC ID behavior. Publisher file, journal, intent and receipt limits remain independent. A frozen plan does not
promise its later intent fits.

## Judgment subjects

Use the public controls `digest` function and its fixed encoding. `preparationDigest` hashes the
complete wire preparation. These subjects bind attributed claims; they authenticate nobody.

| Judgment | Value whose digest is required |
| --- | --- |
| Coverage | `{preparationDigest, coveredMembers}` |
| Grouping | Exact `target` |
| Official selection membership | `{target, members}` |
| Requested extension | `{target, additional}` |
| Unaided assessment and independent review | `{preparationDigest, scope, attemptByteSha256}` |
| No required artifact | `{preparationDigest, output: "revision-note-or-reference"}` |
| Retained artifact reuse | `{preparationDigest, artifactId, contentSha256}` |
| Supersession | Public `activitySupersessionSubject(records, ids, official)` |
