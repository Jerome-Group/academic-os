## Contradictory timing surfaces

Native acceptance must retain each observation's surface, displayed timezone, acquisition time, exact account/list/task identity and numeric saved fields. Match canonical IDs or explicitly verified aliases before comparing observations; a title/date match alone cannot bind identity.

The parent observed contradictory wall-clock readings between Calendar and its embedded Tasks surface while Calendar showed Singapore time. Their cause is unresolved. Never infer a fixed offset, silently correct a plan or infer timing from date-only API fields. Contradictory same-ID observations refuse acceptance and return to cloud investigation. The current single-observation validator is not a substitute for this cross-surface acquisition/contradiction gate. Configured dated/timed writes remain unavailable.
